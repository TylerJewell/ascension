Metallica Chicago Tour Watch

A service that watches public touring signals for an artist in a market, maintains a likelihood and an expected announcement window, and confirms a date only from a source entitled to announce one. A browser console is served from the service itself. User Story 1 is implemented; the free-ticket, evidence, and calibration stories are specified and not yet built.

▶ FanEndpoint HTTP Endpoint /fan The fan's surface: profile, watches, and reads

Accepts a fan profile and a watch registration, returns the current state of a watch, lists active watches, and deactivates a watch. Registering also schedules the first scout cycle five seconds out so a new watch produces something to look at. There is no route that enters a contest, purchases, or reserves anything; the fan is given the official link and acts himself.

FanEndpoint.java
@HttpEndpoint("/fan") @Acl(allow = @Acl.Matcher(principal = Acl.Principal.INTERNET)) public class FanEndpoint { @Post("/watches") public RegisterWatchResponse registerWatch(RegisterWatchRequest request) { if (request.alertWebhookUrl() == null || !request.alertWebhookUrl().startsWith("https://")) throw HttpException.badRequest("alertWebhookUrl must be an https URL"); // The first cycle runs promptly rather than an hour from now. ScoutTickTimer.scheduleNext(timerScheduler, componentClient, watchId, ofSeconds(5)); return new RegisterWatchResponse(watchId); } }
▶ UiEndpoint HTTP Endpoint / Serves the single-page console

Serves the console from src/main/resources/static-resources. The page is a single self-contained file with no external script, stylesheet, or font, so it loads with the service and needs no build step. It calls the same fan API a client would use, which means the console cannot show anything the API does not already expose.

▶ TourWatchEntity Event Sourced Entity tour-watch One fan's standing interest in one artist and market

Holds the journal from which the forecast, the evidence, and the confirmed visits are derived. Two invariants live here because both are silent when broken: a visit can be confirmed only by a source entitled to speak for the artist, and a forecast can be narrated only in terms of signals the watch actually holds. Command handlers carry all validation so that applying an event never fails during replay.

TourWatchEntity.java
public Effect<Done> confirmVisit(ConfirmVisit command) { var source = currentState().findSignal(command.sourceSignalId()); if (source.isEmpty()) return effects().error("No signal to confirm from"); if (!source.get().canConfirmVisit()) return effects().error( "Signal may not confirm a visit: it is a " + source.get().kind() + " from a tier " + source.get().sourceTier() + " source"); if (!currentState().market().contains(command.visit().venue())) return effects().error("Venue is outside the watched market radius"); return effects() .persist(new TourWatchEvent.VisitConfirmed(command.visit())) .thenReply(__ -> Done.getInstance()); }
▶ FanProfileEntity Key Value Entity fan-profile Self-declared attributes eligibility rules read

Stores the fan's home market, residency, age band, memberships, and sponsor relationships. A key value entity rather than an event sourced one because nothing asks for the history of a residency, only its current value. The record holds no payment field, and a test asserts that structurally.

FanProfileEntity.java
@Component(id = "fan-profile") public class FanProfileEntity extends KeyValueEntity<FanProfile> { public Effect<Done> save(FanProfile profile) { if (!profile.fanId().equals(entityId)) return effects().error("Profile fan id does not match entity"); return effects().updateState(profile).thenReply(Done.getInstance()); } }
▶ AlertLedgerEntity Key Value Entity alert-ledger Records what has already been delivered

Holds the fingerprints of alerts already sent for a watch. A fingerprint is claimed before the alert goes out, so a crash mid-delivery costs one missed alert rather than repeated alerts at three in the morning. Because the fingerprint covers the material facts rather than the event, a genuine change alerts again while a redelivery stays quiet.

AlertLedgerEntity.java
// Returns true when this fingerprint had not been sent and is now claimed. public Effect<Boolean> claim(String fingerprint) { if (currentState().hasSent(fingerprint)) return effects().reply(false); return effects() .updateState(currentState().recording(fingerprint, Instant.now())) .thenReply(true); }
▶ TourWatchView View tour-watches Enumerates watches, which an entity cannot

Projects the watch journal into a queryable row. A single watch is read straight from its entity; this exists so that watches can be listed, which an entity keyed by id cannot do. When a forecast is superseded the row's rationale is cleared, because an explanation of the previous estimate shown beside a new number is worse than no explanation.

@Consume.FromEventSourcedEntity(TourWatchEntity.class) public static class TourWatchUpdater extends TableUpdater<WatchEntry> { public Effect<WatchEntry> onEvent(TourWatchEvent event) { /* ... */ } } @Query("SELECT * AS watches FROM tour_watches WHERE active = true") public QueryEffect<WatchEntries> activeWatches() { return queryResult(); }
▶ TourScoutWorkflow Workflow tour-scout One pass over every declared source

Steps through fetch, interpret, and narrate for each source in the registry. Partial failure is the normal case here rather than the exception, so a source that is down degrades the watch's confidence and the cycle continues to the next source. Aborting instead would leave the fan with a stale forecast that looks as solid as a fresh one.

TourScoutWorkflow.java
@StepName("fetch") private StepEffect fetchStep() { var result = gateway.fetch(sourceId, entry.allowedPaths().get(0)); return switch (result) { case FetchResult.Unavailable unavailable -> { componentClient.forEventSourcedEntity(watchId) .method(TourWatchEntity::degradeSource) .invoke(new DegradeSource(sourceId, unavailable.reason())); yield stepEffects().updateState(currentState().advanced()) .thenTransitionTo(TourScoutWorkflow::fetchStep); } case FetchResult.Fetched fetched -> stepEffects() .updateState(currentState().withFetched(...)) .thenTransitionTo(TourScoutWorkflow::interpretStep); }; }
▶ SignalInterpreterAgent Agent signal-interpreter-agent Reads source content into typed signals

Turns promoter prose and calendar notes into typed signal candidates, each carrying a verbatim excerpt from the supplied content. It is not asked how likely a visit is; that number is computed in code. Source, tier, and URL are supplied by the caller from the registry, so nothing the model returns can promote a rumour to an official source. Returning no signals is a correct and expected answer.

SignalInterpreterAgent.java
public record SignalCandidate( @Description("One of the declared signal kinds") SignalKind kind, @Description("One sentence a fan can read") String summary, @Description("How strongly this pushes the estimate") Influence influence, @Description("A verbatim quote supporting this signal") String excerpt) {} public Effect<SignalCandidates> interpret(Request request) { return effects() .systemMessage(SYSTEM_MESSAGE) .userMessage(userMessage) .responseConformsTo(SignalCandidates.class) .thenReply(); }
▶ ForecastNarratorAgent Agent forecast-narrator-agent Explains a forecast already computed

Receives the likelihood, window, and confidence as inputs and writes the explanation. It must not restate, adjust, or contradict the number, and must not state a show date, because a forecast carries an announcement window rather than dates. Its output passes the evidence guardrail before the entity applies it.

ForecastNarratorAgent.java
public record Narration( @Description("Two or three sentences explaining the estimate") String rationale, @Description("The ids this explanation rests on; must not be empty") List<String> citedSignalIds) {} // Rules given to the model: // Never state, adjust, hedge, or contradict the likelihood you were given. // Cite only signal ids from the list provided. // The window is when an announcement is expected, not when the show is.
▶ AlertDispatchConsumer Consumer alert-dispatch-consumer Turns journal events into delivered alerts

Reacts to the watch journal, claims each alert in the ledger before sending, and renders the payload with time remaining computed at the moment of delivery. An alert read six hours after it fired still states how long is left rather than how long was left. A forecast alert is phrased as a forecast on its face so that a prediction cannot be read as an announcement.

AlertDispatchConsumer.java
private Effect dispatch(TourWatchState watch, Alert alert) { boolean claimed = componentClient .forKeyValueEntity(alert.watchId()) .method(AlertLedgerEntity::claim) .invoke(alert.fingerprint()); if (!claimed) return effects().ignore(); var now = Instant.now(); var payload = new AlertPayload( alert.watchId(), alert.kind().name(), alert.headline(), alert.timeToAct(now).toString(), ...); delivery.deliver(watch.alertWebhookUrl(), MAPPER.writeValueAsString(payload)); return effects().done(); }
▶ ScoutTickTimer Timed Action scout-tick Drives the hourly observation cycle

Starts a scout cycle for a watch and schedules the next tick. A watch keeps observing for as long as it is active without anything outside the service having to remember it exists. When the watch is deactivated the timer stops rescheduling, and deactivating through the endpoint deletes the pending timer.

ScoutTickTimer.java
public Effect tick(String watchId) { var watch = componentClient.forEventSourcedEntity(watchId) .method(TourWatchEntity::getWatch).invoke(); if (!watch.active()) return effects().done(); componentClient.forWorkflow(watchId) .method(TourScoutWorkflow::runCycle).invoke(watchId); scheduleNext(timerScheduler, componentClient, watchId, INTERVAL); return effects().done(); }
HTTP routes
▶ GET / Route UiEndpoint.index The console

Returns the console page. It registers a watch, lists active watches, and shows a watch in detail: the likelihood as a meter, the announcement window, the confidence band, the explanation, the cited signals, and any sources currently unreachable. A confirmed visit shows its venue, dates, on-sale time, and the source that announced it. The FORECAST and CONFIRMED badge carries the same distinction the API enforces, so a prediction is never presented as an announcement.

▶ POST /fan/profile Route FanEndpoint.createProfile Creates or replaces the fan profile

Accepts the attributes eligibility rules are evaluated against. Age is a band rather than a birthdate, because a contest asks whether an entrant is over 18 or 21 and that is all this needs to answer. Membership tenure starts on the day the profile is created, so a contest requiring a year of membership reads as unmet rather than assumed satisfied. Returns 201; an unrecognised age band returns 400.

Request
{ "fanId": "saurabh", "displayName": "Saurabh", "homeMarket": "chicago", "residencyState": "IL", "ageBand": "A21_PLUS", "fanClubs": [], "sponsorRelationships": [], "alertWebhookUrl": "https://hooks.example.test/saurabh" }
▶ POST /fan/watches Route FanEndpoint.registerWatch Registers a watch and starts observing

The market carries a centre and a radius rather than a city name, because a fan who wants to see the band in Chicago means the stadium downtown and the amphitheatre an hour out equally. A 50-mile radius from the centre reaches Soldier Field, the United Center, Wrigley Field, Allstate Arena, and the Tinley Park amphitheatre. The webhook must use https. The watch id is the artist slug and market slug joined by a colon.

Request
{ "artistSlug": "metallica", "artistName": "Metallica", "marketSlug": "chicago", "marketName": "Chicago", "centroidLat": 41.8781, "centroidLon": -87.6298, "radiusMiles": 50, "alertThreshold": 60, "alertWebhookUrl": "https://hooks.example.test/saurabh" } // 200 -> { "watchId": "metallica:chicago" }
▶ GET /fan/watches/{watchId} Route FanEndpoint.getWatch Current forecast or confirmed visits

The kind field is mandatory and is either FORECAST or CONFIRMED. It exists so that a client cannot render this payload without knowing which one it holds. The degradedSources list names sources that were unreachable on the last cycle; a non-empty list means the forecast rests on less than the full evidence, and its confidence has been lowered by one level for each blind spot. An unregistered watch returns 404.

Response
{ "watchId": "metallica:chicago", "artist": "Metallica", "market": "Chicago", "active": true, "kind": "FORECAST", "forecast": { "likelihood": 72, "announcementWindow": { "start": "2026-08-29", "end": "2026-10-22" }, "confidence": "MEDIUM", "citedSignalIds": ["hold-1"] }, "confirmedVisits": [], "degradedSources": [] }
▶ GET /fan/watches Route FanEndpoint.listWatches Lists active watches

Reads the view rather than an entity, because an entity keyed by id cannot enumerate its instances. Each summary carries the watch id, artist, market, and current likelihood.

Response
{ "watches": [ { "watchId": "metallica:chicago", "artist": "Metallica", "market": "Chicago", "active": true, "likelihood": 72 } ] }
▶ DELETE /fan/watches/{watchId} Route FanEndpoint.deactivateWatch Stops observing and cancels the timer

Deactivates the watch and deletes its pending scout timer, so observation stops rather than continuing quietly. The call is idempotent and returns 204. The journal is retained, so the evidence and forecast history remain readable after deactivation.

Request
DELETE /fan/watches/metallica:chicago // 204 No Content

▶ forecast-carries-evidence Exit Condition FR-004, FR-016, FR-028 Awaiting approval · test passes

Every forecast the system returns carries at least one evidence signal with a public source and an observation timestamp; a forecast with no evidence is refused rather than served. The rule has two halves. The guardrail sees the model's reply but not what was observed, so it insists citations exist. The entity holds the observed signals, so it rejects citations naming something never seen. Either half alone leaves a route for an unsupported claim to reach a fan.
